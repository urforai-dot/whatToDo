## 설명

모바일/데스크탑 주요 화면의 반응형 레이아웃을 점검하고 수정한다.

## 목표

다양한 화면 크기에서 사용성을 확보한다.

## 관련 요구사항 (개발요구사항문서.md)

> STEP 4 - 제약: 1인 바이브 코딩 (최소 품질 기준 확보)

## 완료 조건 (Acceptance Criteria)

- [x] 코드 레벨로 점검·수정함: 업무 목록 행이 360px에서 고정폭 컬럼(모델/담당자/상태)들 때문에 제목이 거의 안 보이던 문제를 발견해 `hidden sm:inline`/`md:inline`으로 좁은 화면에서 숨김, 담당자 텍스트에 `max-w-20 truncate` 추가. 대시보드 2열 그리드는 `lg:` 미만에서 1열로 스택.
- [ ] **실제 좁은 뷰포트 스크린샷으로 최종 확인은 못함** — 이 환경의 브라우저 자동화 도구가 창 크기를 바꿔도 스크린샷 해상도가 안 바뀌는 문제가 있었음(도구 한계). 데스크탑 폭에서는 실제 스크린샷으로 확인함(대시보드/이력 페이지, 에러 상태 포함).

## 메모

360px 기준 실제 기기/브라우저 개발자도구로 한 번 더 확인하는 걸 권장. 특히 업무 목록 행의 P{n}+제목+마감일만 남는 좁은 레이아웃이 실제로 읽기 편한지는 사람이 보는 게 가장 정확하다.
