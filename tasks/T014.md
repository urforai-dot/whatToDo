# T014 — 담당자별 워크로드 집계 API

- **단계(phase)**: 백엔드 API (backend-api)
- **상태**: done
- **예상 소요**: 30분
- **선행 작업(dependencies)**:
- T010

## 설명

GET /api/workload 구현: 담당자별 진행 중 업무 수/예상 소요시간 합계를 계산해 반환한다.

## 목표

누가 얼마나 여유가 있는지 한눈에 파악할 수 있는 데이터를 제공한다.

## 관련 요구사항 (개발요구사항문서.md)

> STEP 2 - 누가 지금 얼마나 여유가 있는지도 안보임

## 완료 조건 (Acceptance Criteria)

- [x] GET /api/workload가 담당자(10명 전원, 업무 0건인 사람 포함)별 전체 업무 수, 진행중 업무 수, 가장 가까운 마감일을 반환함
- [x] LEFT JOIN이 WHERE 절 때문에 사실상 INNER JOIN이 되어 업무 0건인 담당자가 누락되는 일이 없음 (adversarial-reviewer가 지적, `and(eq(...), ne(status,'done'))`을 JOIN의 ON 절 안으로 옮겨 수정)

## 메모

- **"예상 소요시간 합계" 요구사항 제거**: 개발요구사항문서.md에는 업무별 예상 소요시간을 사용자가 입력/조회한다는 내용이 없다. 이 AC는 우리 자체 개발 백로그(backlog.json)의 `estimated_minutes`(30분 단위 작업 관리용) 개념과 제품 자체의 요구사항을 혼동해서 잘못 작성된 것으로 판단, T006과 함께 제거했다. 실제로 필요한 건 "누가 여유 있는지"이므로 업무 수 + 진행중 수 + 다음 마감일로 대체.
