# T034 — 코멘트에서 #업무번호로 다른 업무 참조/링크

- **단계(phase)**: misc
- **상태**: done
- **예상 소요**: 30분
- **선행 작업(dependencies)**:
- T017

## 설명

git PR/이슈 참조(`#71`)처럼, 코멘트 본문에 `#<업무번호>`를 쓰면 그 업무로 바로 이동하는 링크가 되게 한다. 한 코멘트에 여러 개 참조해도 됨. (2026-09-17 사용자 지시)

## 목표

연관 업무나 이력을 텍스트 안에서 가볍게 서로 엮을 수 있게 한다 — 별도 "연결" UI 없이 코멘트 쓰는 흐름 그대로.

## 완료 조건 (Acceptance Criteria)

- [x] 코멘트 본문에서 `#123` 형태의 토큰이 클릭 가능한 링크로 렌더링됨 (`src/components/dashboard/linked-text.tsx`)
- [x] 링크 클릭 시 해당 업무의 TaskDetailPanel이 열림 (대시보드/이력 페이지 둘 다 — `onOpenTask` prop을 `setSelectedTaskId`로 연결)
- [x] 참조는 여러 개 가능함 (`text.split(정규식)`이라 개수 제한 없음)
- [x] 참조 대상 업무 id를 사람이 알아야 하니, 상세 패널 제목에 `#{id}`를 노출함 (T032에서 이미 작업)
- [x] 존재하지 않는 번호를 참조해도 앱이 죽지 않음 — TaskDetailPanel이 이미 가진 404 에러 처리("업무를 불러오지 못했습니다")로 자연스럽게 커버됨, 별도 유효성 검사 안 함
- [x] 브라우저로 실제 확인: `#1` 코멘트를 달았을 때 상세 패널에 코멘트가 링크 스타일로 표시되고, 클릭하면 해당 업무로 정확히 이동함

## 메모

- DB 스키마 변경 없음 — 별도 "관련 업무" 테이블/필드를 만들지 않고, 코멘트 텍스트를 렌더링 시점에 파싱하는 방식으로 구현함(git이 커밋 메시지/PR 본문의 `#71`을 렌더링 시점에 링크로 바꾸는 것과 같은 방식). "여러 개 참조 가능"도 텍스트에 여러 번 쓰면 되니 자연히 됨 — 별도 다대다 관계 설계가 필요 없었음.
- 존재 여부를 미리 확인(전체 업무 목록을 fetch해서 대조)하지 않음 — 섹션원 10명, 업무 10여 건 규모의 내부 도구에서 그 정도 검증까지는 과하다고 판단. 잘못된 번호를 클릭하면 상세 패널이 이미 가진 에러 상태가 뜨는 것으로 충분한 피드백이 됨.
- `description` 필드(스키마엔 있지만 편집 UI가 아직 없음)에는 이 링크 파싱을 적용하지 않음 — 애초에 description을 보여주는 화면 자체가 없어서 범위 밖.
