## 설명

4대 핵심 시나리오(접속→우선순위/워크로드 확인→업무 추가→완료 업무 확인)를 처음부터 끝까지 수동으로 점검한다.

## 목표

실제 요구사항 문서의 핵심 시나리오가 끊김 없이 동작하는지 확인한다.

## 관련 요구사항 (개발요구사항문서.md)

> STEP 4 - 핵심 사용 시나리오 1~4

## 완료 조건 (Acceptance Criteria)

- [x] **실 데이터로 4대 시나리오 전체를 끝까지 통과시킴** (2026-09-17, Supabase 연결 후) — 브라우저(claude-in-chrome)로 실제 클릭 테스트:
  1. 로그인 페이지에서 실 사용자 10명(섹션원1~10 아님, 김민수/박서연 등 실명) 드롭다운 확인 → 김민수로 로그인
  2. 대시보드에서 우선순위(P1~P4) 정렬, 마감 임박 위젯, 담당자별 워크로드 위젯 정상 표시
  3. 하단 업무 추가 바로 "브라우저 QA 테스트 업무 / 모델X / 2026-09-25" 입력 → 등록 → 목록/마감위젯에 즉시 반영 확인 (테스트 후 DB에서 정리함)
  4. 업무 행 클릭 → 상세 패널에서 코멘트 작성(등록) → 상태를 완료로 변경 → `/history`(이력)에서 해당 업무 + 코멘트 노출 확인 (테스트 후 원 상태로 복구)
  5. 로그아웃 → 로그인 페이지로 리다이렉트 → 정하늘로 재로그인, 세션 전환 정상
- [x] 발견된 문제는 T017 이하 각 task의 메모에 기록함 (adversarial-reviewer가 찾은 백엔드 버그들, 디자인 의도적 이탈사항들)

## 메모

**T004(Supabase) 연결 후 완료함.** 진행 순서:
1. `npm run db:migrate` (drizzle/0000~0003 적용, 이미 존재하던 테이블에 맞춰 `__drizzle_migrations` 추적 테이블을 해시 백필)
2. `npm run db:seed` (12개 샘플 업무, 10명 유저, 5개 코멘트)
3. 로그인 → 우선순위/워크로드 확인 → 업무 추가(add-task-bar) → 상세 패널에서 코멘트 작성 → 상태를 done으로 변경 → `/history`에서 확인 — 전부 실제 클릭 테스트로 통과
4. curl/node fetch로 API 레벨도 별도 검증함 (필터/정렬/검증 에러/인증 401/코멘트 작성자 세션 고정 등) — T010~T014 메모 참고

추가로 발견한 이슈: Windows Git-Bash의 curl에 한글 인자를 직접 넘기면 코드페이지 문제로 깨진다(앱 버그 아님, 로컬 셸 환경 문제). node fetch로 재확인해 정상 UTF-8 인코딩 확인함.
