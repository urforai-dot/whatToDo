# T032 — 업무 시작일 설정/수정 UI

- **단계(phase)**: misc
- **상태**: done
- **예상 소요**: 30분
- **선행 작업(dependencies)**:
- T031

## 설명

업무 생성 폼(add-task-bar)과 상세 패널에서 시작일(startDate)을 입력/수정할 수 있게 한다. DB 스키마·API는 이미 startDate를 지원하고 있었지만(POST/PATCH 둘 다 zod 스키마에 있었음) UI에서 실제로 값을 보내는 경로가 없었다. (2026-09-17 사용자 지시 — T033 간트 달력의 전제조건)

## 목표

달력을 시작일~마감일 바(Gantt)로 보여주려면 업무에 시작일이 실제로 들어가야 한다.

## 완료 조건 (Acceptance Criteria)

- [x] `add-task-bar.tsx`의 빠른 추가 입력이 "제목 / 모델 / 시작일 / 마감일" 형식을 지원함 — 기존처럼 마감일 하나만 써도 되고(하위호환), 뒤에서부터 날짜로 보이는 세그먼트를 최대 2개까지 시작일/마감일로 읽음
- [x] `TaskDetailPanel`에 시작일/마감일 date input 2개를 추가해서 기존 업무도 언제든 수정 가능함 (상태/우선순위 셀렉트와 같은 줄, 변경 즉시 PATCH)
- [x] 상세 패널 제목에 `#{id}`를 표시함 (T034 해시태그 참조 기능에서 사용자가 참조할 ID를 알 수 있어야 함)

## 메모

- API(`POST /api/tasks`, `PATCH /api/tasks/:id`)는 이미 startDate를 받고 있었어서 백엔드 변경 없음 — UI만 이어붙임.
- 날짜 input은 네이티브 `<input type="date">` (shadcn Input 그대로) — 별도 date picker 라이브러리 없이 브라우저 기본 위젯 사용.
- 시작일이 마감일보다 늦어도 막지 않음 — DB/zod 둘 다 순서 제약이 없고, 사용자가 요청한 범위도 아님.
- **adversarial-reviewer가 찾은 실제 버그**: 처음 버전은 `onChange`에서 바로 `patchTask`를 호출했는데, 네이티브 `<input type="date">`는 세 자리(연/월/일)가 다 채워지기 전 입력 도중에도 `value=""`로 `onChange`가 여러 번 발화한다. 즉 날짜를 고치려고 타이핑하는 중간에 시작일이 null로 지워지는 사고가 날 수 있었음. `startDraft`/`dueDraft` 로컬 상태로 화면에 보이는 값만 추적하고, 실제 PATCH는 `onBlur`(입력 완료 후 포커스가 빠질 때)에만 보내도록 고침. 브라우저 JS로 `focusout` 이벤트를 직접 발생시켜 재현 확인함(주의: 합성 `blur` 이벤트는 React가 못 받고 `focusout`이어야 React의 onBlur가 반응함).
