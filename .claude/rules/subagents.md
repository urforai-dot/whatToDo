# Subagent 사용 규칙

이 프로젝트에는 전용 subagent 2개가 `.claude/agents/`에 정의되어 있다. 둘 다 **자동으로 실행되지 않는다** — 아래 시점에 오케스트레이터(메인 세션)가 직접 `Agent` 툴로 호출한다.

## `backlog-briefer` (Haiku, 수동 호출)

**언제**: backlog task 하나를 실제로 시작하기 직전. task id를 프롬프트로 주고 호출한다.

**하는 일**: `node scripts/backlog-cli.js show <id>`로 task를 읽고, 쉬운 말로 설명하고, 관련 파일을 찾아 `tasks/<id>.md`의 `## 쉬운 설명` / `## 관련 파일` 섹션을 채운다.

**쓰는 이유**: task 하나를 시작할 때마다 관련 파일을 처음부터 다시 훑는 대신, 값싼 모델로 먼저 지도를 그려두고 시작한다. 이미 `## 관련 파일`이 채워져 있고 최신이면 다시 부를 필요 없다.

## `adversarial-reviewer` (Opus, 수동 호출)

**언제**: 한 task 안에서 의미 있는 파일 생성/수정을 마쳤을 때 — 예를 들어 새 API route, 새 컴포넌트, 스키마 변경처럼 실수가 조용히 묻히기 쉬운 변경. 오타 수정이나 한 줄짜리 변경마다 부르지 않는다 (Opus라 비용/시간이 든다).

**하는 일**: 방금 바뀐 파일을 읽고, 해당 task의 완료 조건에 비춰 일부러 적대적으로 트집을 잡는다. 파일을 고치지 않고 보고만 한다.

**받은 뒤**: 지적을 그대로 수용하지 말고, 실제로 맞는지 코드를 다시 확인한 뒤 고칠 건 고치고, 아니면 왜 아닌지 판단해서 넘어간다. `needs_review` 상태로 바꾸고 사용자에게 판단을 넘겨도 된다.

## 일반 subagent 사용 원칙 (Claude Code 공통 정책)

- 사용자가 명시적으로 요청하지 않는 한, subagent를 남발하지 않는다. 짧은 조사/한 파일짜리 변경은 직접 한다.
- 결과를 다시 참고할 필요 없는 열린 질문/조사는 `fork`로 띄운다.
- `backlog-briefer`/`adversarial-reviewer`처럼 이름이 있는 subagent를 부를 때는 그 agent의 `description`에 맞는 시점에만 부른다 — 범위를 벗어난 일을 시키지 않는다.
